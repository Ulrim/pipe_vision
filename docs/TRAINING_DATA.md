# 직접 만든 학습·평가 데이터 (vision.synth) — 2026-10-24

> **이 문서의 모든 수치는 직접 만든 데이터로 잰 것이다 — 인수 증빙(FAT/SAT)이 아니다.**
> 실제 정확도는 광학 셋업(60cm·카메라 모듈 3) 뒤 실물 정답셋(`AIVIS_DATASET_DIR`)으로 다시 잰다(CLAUDE.md §1.2).

실물 정답셋이 모이기 전에 할 수 있는 일은 두 가지다.
1. **정답을 아는 장면을 대량으로 만들어** 개수·길이 알고리즘이 어디서 틀리는지 찾고 고친다.
2. **표면 불량을 그려 넣은 튜브 사진으로** 표면 모델(ONNX)을 미리 학습해 둔다.

공개 저장소에는 **생성기 코드만** 넣는다. 현장 사진, 그 사진에서 잘라 낸 질감, 그것으로 학습한 모델은 넣지 않는다
(저장소가 공개다). 생성기가 만드는 데이터는 시드 고정이라 같은 명령이면 같은 데이터가 다시 나온다.

## 1. 무엇을 만드나

| 구성 | 내용 |
|---|---|
| 튜브 한 개 (`synth/tube.py`) | 원통 음영(가장자리 어둡게), 정반사 띠·2차 반사, 축 방향 반사 변화, 압출 결, 절단면 그늘. 끝면(구멍)은 비스듬히 찍을 때만 — 위에서 수직이면 끝면은 카메라 반대쪽을 본다 |
| 표면 불량 (`synth/defects.py`) | 스크래치(가는 선, 방향·길이·깊이), 유분기(무광 얼룩 + 옅은 광택), 변색(금→주황→갈색 단계), 복합, **경계 샘플**(옅은 불량, `border=true`) |
| 장면 (`synth/scene.py`) | 배치(붙음·틈·섞임·떨어짐), 끝 엇갈림, 튜브마다 길이 편차·공차 밖(LEN), 배경(무광 검정·밝은 트레이·밝은 바닥), 그림자, 기준자(10mm 눈금), 회전, 원근, 조명 기울기, 흐림·잡음·JPEG |
| 정답 | 장면마다 json: 튜브별 네 모서리·길이(mm)·라벨, 배율(mm/px), 원근 행렬 |
| 표면 학습셋 (`synth/dataset.py`) | 부록 A.4 형식 `raw/<CLS>/*.jpg + 사이드카` — 파이프라인이 표면 판정에 넘기는 영역(튜브 몸통)과 같은 자르기 |

장면 종류(`random_spec`):

- **production** — 현장 확정 조건: 무광 검정, 위에서 수직(원근 없음), ±3°, 기준자, 붙음/틈/섞임.
- **tray** — 밝은 트레이 위 다발(대표님 사진 시험 조건): 큰 회전, 일부 원근.
- **floor** — 밝은 바닥 위 떨어진 튜브 3~8개.
- **hard** — 강한 원근·큰 회전·흐림·저대비(한계 확인용).

## 2. 쓰는 법

```bash
cd services
# 표면 학습셋(정상 600·SCR/OIL/DIS 각 300·복합 150·경계 240, 시험셋 1/4) + 장면 180장
python -m vision.tools.build_training_data --out /data/synth
# 현장 사진 질감을 섞으려면(사진 단위로 학습/시험 분리)
python -m vision.tools.build_training_data --out /data/synth --real-dir ~/photos

# 개수·길이 평가 (외경 기준정보를 넣고 재려면 --od)
python -m vision.tools.eval_scenes --scenes /data/synth/scenes --report /data/eval

# 표면 모델 학습 → ONNX surface3 + 사이드카 (torch 는 학습 PC 에만)
python -m vision.models.train_surface --train /data/synth/train --test /data/synth/test --out runs/surface
# 표면 평가 — 고전 CV 와 ONNX 를 배포 경로 그대로 비교
python -m vision.tools.eval_surface --data /data/synth/test --report /data/eval_surface --onnx runs/surface/surface.onnx
```

배포: `AIVIS_SURFACE_ONNX=<경로>/surface.onnx` (사이드카 `surface.json` 이 같은 폴더). **기준정보의 표면 임계를
사이드카의 `recommended_thresholds` 로 바꾼다** — 고전 CV 점수와 척도가 다르다.

## 3. 개수·길이 — 장면 180장 평가

같은 장면(시드 20261026)에 어제 코드(커밋 511a403)와 오늘 코드를 돌린 결과.

| 장면 종류 | 장면 | 개수 정확도 (전 → 후) | 비고 |
|---|---|---|---|
| production (현장 조건) | 60 | **10.0% → 100%** | 불일치 검출 15/15 |
| floor (밝은 바닥 낱개) | 30 | 33.3% → 93.3% | |
| tray (밝은 트레이 다발) | 60 | 50.0% → 60.0% | 붙은 무리 사이에 작은 틈이 섞인 다발이 약점(붙음만이면 정확) |
| hard (강한 원근) | 30 | 13.3% → 46.7% | 한계 확인용 |
| **전체** | 180 | **27.8% → 76.7%** | 기대 개수와 다를 때 불일치 검출 45/45 |
| field (현장 변형, 오늘 추가) | 80 | 100% | 덜 검은 바닥·먼지·카메라 기욺·조명 기울기·흐림·최대 40개 |

현장 조건 길이(원근 없음, 개수 맞은 장면, 0.354mm/px — 반 해상도): 길이 σ **0.17mm**, 끝 못 찾음 0%,
일정한 치우침 −0.43mm(절단면 그늘을 끝단 안쪽으로 읽음 — 아래 4절), **치우침 보정 뒤 LEN 판정 일치 98.9%**.
전체 해상도(4608×2592, 0.177mm/px, 튜브 20개)에서는 개수 정확, 길이 σ 0.006mm, 치우침 −0.14mm.
처리시간은 같은 프레임 0.2초(튜브당 약 10ms, 이 개발 PC — 파이는 몇 배 느리다. 방향 판단이 전체 해상도를
덩어리마다 훑던 것을 고쳐 1.4초에서 줄였다).

대표님 현장 사진(밝은 트레이 19개 × 10장, 밝은 바닥 4개 × 7장)은 오늘 코드로도 종전과 같다 — 트레이 9/10 정확,
1장(t07)은 20개로 세되 '불확실 → 재확인' 표시, 바닥 7/7 정확.

### 어제 코드가 틀린 이유와 고친 것

1. **다발이 화면 폭의 30% 보다 좁으면 하나도 못 찾았다.** 튜브가 있는 행을 '화면 폭의 30% 넘게 덮인 행' 으로
   찾았기 때문이다. 60cm 설치에서 250mm 튜브가 딱 화면 폭의 약 30% 다 — 현장에서 바로 터질 조건이었다.
   → 배치 찾기(`multi/layout.py`): 제품 마스크의 덩어리마다 자기 축으로 길이·폭을 잰다.
2. **3° 만 기울어도 개수가 무너졌다**(튜브 사이 골을 가로 평균으로 찾음). → 덩어리 자기 축으로 잰다.
3. **기준자(눈금 띠)를 튜브로 셌다.** → 축 방향 밝기가 주기적으로 바뀌면(눈금) 기준자로 보고 뺀다.
4. **큰 다발·기운 조명에서 배경 밝기를 거꾸로 판단했다.** → 화면 테두리 밝기 ÷ 가장 밝은 곳 비율.
4-1. **덜 검은 바닥에서 튜브 하나를 둘로 셌다**(전역 Otsu 문턱이 튜브 밝기 한가운데). → 배경 화소만으로 배경을
   추정하고, 배경 잡음의 5배와 튜브 쪽 차 중앙값의 25% 중 큰 값을 문턱으로.
5. **붙은 덩어리를 나눌 '튜브 한 개 폭'** — 기준정보 외경(`outer_diameter_mm` ÷ 배율, 마스크 폭에 맞춰 척도 보정)이
   있으면 그것, 없으면 붙은 덩어리 안 골 간격 → 가는 덩어리 중심 간격 → 폭 정수배. 외경 입력 유무에 따른 차이:
   현장 조건·현장 변형은 둘 다 100%, 전체 180장은 입력 75.0% · 미입력 76.7%(밝은 바닥 한 장 차이).
6. **밝은 바닥에서 떨어진 튜브 둘이 한 덩어리**(마스크 다듬기가 틈을 메움) → 바닥 밝기 띠(틈)로 먼저 가른다.
7. **띠 측정에서 끝단을 놓쳤다**(튜브 9개 중 4개) → 배치 찾기가 준 끝을 출발점으로 넘긴다.
8. **줄무늬 분석이 가장자리 튜브 하나를 빠뜨렸다** → 빈 구간이 한 폭이면 마스크로 채우고, 아니면 재확인.
9. **밝은 바닥 무늬를 수십~수백 개로 셌다** → 낱개가 3개 이상 잡히면 줄무늬 간격·개수를 대조해 버린다.

개수가 애매하면(덩어리 폭과 골·줄무늬 셈이 어긋남, 경계 여유 부족) **배치 NG + 튜브 전부 재확인**으로 보낸다 —
조용히 고르지 않는다.

## 4. 길이 치우침 — 마스터 시료로 보정

끝단은 절단면 테두리가 약간 어둡게 보여 바깥보다 반 화소쯤 안쪽에서 읽힌다(양 끝 합쳐 약 1px). 장면마다 같은
방향·같은 크기라 **길이를 아는 튜브(마스터 시료, 캘리퍼 측정값)로 한 번 재서 빼면** 된다. MSA 의 '치우침(bias)'
항목과 같은 절차다. 기준정보 촬영 레시피에 `"length_offset_mm": <평균(캘리퍼 − 측정)>` 를 넣는다(스키마 변경 없음,
온도 환산 전에 더한다). 절차는 `docs/FIELD_SETUP.md` §5, 계산 도구 `python -m vision.tools.calibrate_offset`.

## 5. 표면 — 고전 CV 와 학습 모델

직접 만든 표면 시험셋(473장, 학습과 다른 시드·다른 현장 사진 질감)에서 배포 경로 그대로 잰 값.

| 방식 | 유분기 검출률 | 변색 검출률 | 스크래치 검출률 | 정상 오경보(합성) | 현장 정상 튜브 오경보 | 장당 |
|---|---|---|---|---|---|---|
| 고전 CV(현재 기본값, 임계 0.30/0.20/0.15) | 85.7% | 13.2% | 97.7% | 99.3% | **100%** | 1.78 ms |
| ONNX 학습 1차 | 61.9% | 99.2% | 56.5% | 4.7% | **8.1%** | 7.92 ms |
| ONNX 2차(증강 강화) | 67.5% | 99.2% | 84.0% | 6% | **29.7%** | 7.34 ms |
| ONNX 3차(+현장 정상 튜브 236장) | 67.5% | 98.4% | 45.0% | 5.3% | **0%** | 7.6 ms |
| ONNX 4차(3차 데이터, 60 에포크) ← 권장 | 63.5% | 99.2% | 75.6% | 6% | **0%** | 2.15 ms |

검출률은 합성 정상 오경보가 약 2% 가 되게 잡은 임계(사이드카 `recommended_thresholds`)에서. 고전 CV 는 현재 기본 임계 —
거의 모든 튜브를 불량으로 봐서 검출률이 높아 보일 뿐이다. 현장 정상 튜브 = 학습에 쓰지 않은 사진 2장(t09·t10)의 74장.
'장당' 은 이 개발 PC 에서 잰 값으로 측정 때 부하(동시 학습)에 따라 2~8ms 로 흔들렸다 — 모델 크기는 모두 같다.

다발 장면 통째로(배포 경로 `inspect_batch(stage=POST_WASH_SURFACE)`, 현장 조건 60장 · 튜브 1,039개, 경계 샘플 포함)
권장 모델(4차)로: 유분기 50/62 · 변색 47/47 · 스크래치 41/50 검출, 정상 튜브 오경보 26/897(2.9%).

- **고전 CV 는 실제 같은 튜브 사진에서 쓸 수 없다.** 반사 띠·압출 결을 스크래치·유분기로 읽어 정상 튜브의
  거의 전부를 불량으로 본다(점수가 0·1 로 몰려 임계를 어디에 두어도 오경보를 못 줄인다). 지금까지 시험이 통과한
  것은 단색 도형으로 만든 예전 합성 이미지였기 때문이다.
- 학습 모델은 이 데이터에서 변색은 거의 완벽, 유분기·스크래치는 정상 오경보 2% 에서 검출률 유분기 63.5%·스크래치 75.6%(권장 v4).
- **현장 사진의 정상 튜브**(학습에 안 쓴 사진 2장, 74장)에서 오경보 0%(권장 v4; 2차는 30%) — 직접 만든 데이터와 실물 사이의
  차이가 여기서 드러난다. 실물 불량 사진은 하나도 없으므로 **실물 검출률은 아직 모른다.**

## 6. 남은 한계와 다음 단계

|---|---|---|
| 현장 조건 개수 | 직접 만든 장면 100% | 60cm 실물 사진(무광 검정 바닥·기준자)으로 확인 |
