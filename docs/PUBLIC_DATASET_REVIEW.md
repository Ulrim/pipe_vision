# 공개 데이터셋 전수 검토 결과 — `02. 파이프 데이터셋_260920`

구글드라이브 폴더를 **폴더 단위로 전수 열람**하고, 그중 실제로 픽셀까지 읽은
분량과 거기서 나온 측정값을 정리한다. 이전 보고에서 틀렸던 판단 두 가지도
여기서 정정한다.

## 1. 폴더 전수 구성 (실측)

| 구성 | 내용 | 수량 |
|---|---|---|
| `Class1` ~ `Class6` | DAGM 2007 표면결함 벤치마크 | 6개 클래스 × (Train 575 + Test 575) = **6,900장** |
| `Steel Pipe Size Detection -2-.v2i.coco` | 강관 **단면 번들** 사진 + COCO 정답 | train / valid / test 3개 split |
| `…v2i.yolov8`, `…v2i.yolov11` | 위와 **같은 사진**, 라벨 포맷만 다름 | (중복) |

DAGM 각 split 의 결함 수량은 `Label/Labels.txt` 전수를 받아 확인했다.
클래스마다 결함 분포가 다르다(예: Class4·Class5 는 Train 끝단 1141~1150 이
연속 결함 블록, Class2 는 1059 이하에만 결함).

## 2. 실제로 픽셀까지 읽은 분량

| 데이터 | 읽은 양 | 비고 |
|---|---|---|
| 강관 **test split** | **54장 / 54장 (100%)**, 정답 박스 **22,187개 전수** | 이번에 전부 |
| DAGM Class1 | 100장 (Train 49 / Test 51) | 이전 세션 |
| DAGM Class2~6 | 색인(결함 목록·수량)은 전수 확인, 픽셀은 미열람 | §5 참조 |

## 3. 정정 ①: 강관 데이터셋은 "쓸모없는 자료"가 아니다

이전에 이 데이터셋을 한 장만 열어보고 촬영품질 판독기에 넣어
**"한 프레임에 2개 — 1프레임 1개 규격 위반(A.3)"** 으로 분류했다. 틀렸다.
실제로는 한 프레임에 **84~932개**(중앙값 364개)의 파이프 단면이 들어 있고,
단면마다 사람이 그린 bbox 와 호칭경(1/2/3인치) 라벨이 붙어 있다.
판독기가 2개로 센 것은 다객체 검출 규칙이 이 밀도를 전제하지 않아서다.

이 구도는 **에이엠피 1차 자료의 크레이트 단면 샷과 같은 구도**이고,
CLAUDE.md §A.1 이 "크레이트 단면 면스캔 = 변색·유분기 **1차 스크리닝** 옵션"
으로 남겨둔 바로 그 장면이다. 즉 용도는 분명히 있다.

## 4. 정정 ②: 이 데이터셋으로 `segment_tubes()` 를 검증할 수는 없다

앞서 "실사진 + 정답 박스로 `multi/segment.py` 를 정량 검증할 수 있다" 고
했는데 이것도 틀렸다. `segment_tubes()` 는 **옆으로 누운** 튜브가 나란히
쌓인 장면을 1차원 밝기 프로파일의 골로 가르는 알고리즘이고 상한이 20개다.
단면 번들은 2차원 조밀 충전된 원이 수백 개라 가정 자체가 다르다.

그래서 이 구도를 위한 모듈을 따로 만들었다 — `services/vision/multi/bundle.py`.

## 5. 측정 결과 — 고전 CV 로는 부족하다 (전수 54장)

`count_bundle()`(CLAHE → 적응형 임계 → 거리변환 봉우리 → 비최대억제)을
**test split 전수 54장 / 정답 22,187박스**에 대고 격자탐색으로 최적화한 결과:

| 지표 | 값 |
|---|---|
| 정밀도 (precision) | 0.401 |
| 재현율 (recall) | 0.342 |
| F1 | **0.369** |
| 개수 오차 (MAPE) | 76.4% |
| 처리속도 p50 / p95 | 19.6 ms / 31.1 ms |

HoughCircles 로도 바꿔 봤지만 F1 0.52(20장 부분집합 기준)로 더 나빴고,
전수로는 더 떨어졌다.

**결론: 창고 조명·겹침 조건의 단면 번들 계수는 고전 CV 로 안 된다.**
속도는 20ms 로 충분하지만 정확도가 수량 검수에 쓸 수준이 아니다.
이 구도를 실제로 쓰려면 **학습 기반 검출기(YOLO 계열)** 가 필요하고,
마침 이 데이터셋의 train split 이 그 학습 데이터다.

> 이 수치는 **강관**에서 잰 값이다. 에이엠피는 알루미늄이라 표면 반사·색이
> 달라 임계값을 그대로 옮길 수 없다. 여기서 확인한 것은 "이 구도에서
> 고전 CV 가 어디까지 가는가" 라는 방법의 한계다.

재현:

```bash
python -m vision.tools.bundle_benchmark \
    --images <강관 test 이미지 폴더> \
    --coco   <test/_annotations.coco.json>
```

## 6. 남은 일과 제약 — 왜 DAGM Class2~6 픽셀을 다 못 읽었나

이 세션에서 드라이브 파일을 가져오는 경로는 **커넥터뿐**이고, 다음 제약이 있다.

- 파일 1개당 호출 1회. 폴더 목록은 1회에 10개.
- `drive.google.com`, Zenodo, Kaggle, HuggingFace 는 이 환경의 송신 정책에서
  차단되어 있어 일괄 내려받기가 불가능하다(GitHub 만 허용).

DAGM 6,900장을 전부 읽으려면 호출이 약 7,600회 필요하다. 그래서 이번에는
**색인(결함 목록·수량)은 6개 클래스 전수**로 확인하고, 픽셀은 강관 test
전수 + Class1 로 한정했다.

**가장 빠른 해결책**: 데이터셋을 **ZIP 한 개로 묶어** 드라이브에 올려주시면
호출 1회로 전부 받을 수 있다. 그러면 DAGM 6개 클래스 전수 벤치마크와
강관 train split 기반 학습 검출기까지 한 번에 진행 가능하다.

## 7. 현장 사진에서 확인된 것 — 공정이 "다발 동시 절단"이다

`02. 파이프 데이터셋_260920 / 01. 현장 및 실제 파이프 이미지, 영상` 의
실사진을 열람한 결과, **부록 A 가 전제한 제품 흐름과 실제 공정이 다르다.**

| 사진 | 내용 |
|---|---|
| IMG_1574 / 1575 | 절단기 출력부. **긴 튜브 수십 개가 나란히 누워** 랙에 놓인다 |
| IMG_1583 / 1584 / 1585 | 절단기 클램프 내부. 튜브를 **11~12단으로 적층해 한 번에 동시 절단** |

함의:

1. **§A.3 의 "1프레임 = 1개(다발 금지)" 는 이 공정과 맞지 않는다.** 제품은
   애초에 다발로 잘려 다발로 나온다. 1개씩 분리(singulation)하려면 별도
   설비가 필요하고, 그건 본 사업 범위(§2) 밖의 하드웨어다.
2. 따라서 길이 검사는 **측면 다수 튜브 구도에서 N개 동시**로 설계해야
   현실적이다. 이 구도는 `multi/segment.py segment_tubes()` 가 상정한
   바로 그 장면이지만, **상한 20개(MAX_TUBES_HARD)** 로는 부족할 수 있다
   (클램프 사진 기준 한 단면에 수십 개).
3. 단면 번들 구도(§A.1)도 실재한다 — 적재/크레이트가 아니라 **절단기
   클램프 안**에서 나타난다.

> 촬영 가이드(§A.3)와 `MAX_TUBES_HARD` 는 현장 확인 후 함께 재조정이 필요하다.

## 8. 길이(mm) 학습 데이터셋 — 공개된 것이 없고, 있어도 못 쓴다

찾아본 결과 **파이프 길이에 mm 정답이 붙은 공개 이미지 데이터셋은 없다.**
없는 것이 당연하다. 길이 정답은 카메라–대상 거리·렌즈·광학 배율에 종속되어
**셋업이 바뀌면 같은 사진도 다른 mm 가 된다.** 그래서 이 분야는 데이터셋이
아니라 **기준물 동시 촬영 + 캘리브레이션**으로 푼다(자·ArUco·게이지 블록).
우리 §6.2 구현(서브픽셀 엣지 + 품목별 px→mm 보정계수)이 이미 그 방식이다.

즉 길이는 "학습" 문제가 아니라 **캘리브레이션·계측** 문제이고, 정답 데이터는
**현장에서 캘리퍼스 실측값과 함께 직접 만들어야** 한다.

## 10. 두 번째 벤치마크 — 고전 CV 는 일반화하지 못한다 (확정)

`count_bundle()` 을 **강봉 데이터셋 93장(정답 14,814개)** 에 그대로 걸었다.

| 데이터셋 | 정밀도 | 재현율 | F1 | 개수오차 |
|---|---|---|---|---|
| Steel Pipe (창고 번들) | 0.401 | 0.342 | 0.369 | 76% |
| **Steel-bar (강봉 단면)** | **0.034** | 0.402 | **0.063** | **1,883%** |

같은 파라미터로 F1 이 0.37 → 0.06 으로 무너졌다. 19배 과검출이다.
**결론이 분명해졌다: 단면 번들 계수에 고전 CV 는 쓸 수 없다.** 한 데이터셋에
맞춘 임계값이 다른 데이터셋에서 전혀 작동하지 않으므로, 현장 조명이 바뀌는
실제 운영에서는 더 나쁠 것이다. `multi/bundle.py` 는 **학습 검출기의
비교 기준선(baseline)** 으로만 남긴다.

학습 검출기를 붙일 재료는 이제 갖춰졌다 — 강봉 93장 14,814박스 +
강관 54장 22,187박스 = **정답 37,001개**.
