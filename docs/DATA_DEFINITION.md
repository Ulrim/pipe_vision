## 작성 메모 (제출 전 삭제)

- **【확인】** 표시는 관리기관 또는 양 기업이 확정해야 하는 값이다. 확정 후 표시를 지운다.
  1. 과제명 정식 명칭, 총괄책임자 성명·직위·연락처·이메일, 데이터 유통 담당부서·담당자·전화·이메일(1-1, 2절)
  2. 산업분류 코드 — 양식 붙임3에 제조·금속가공 분류가 없음(농축수산/국토환경/기타만 수록). 관리기관에 코드 확인
  3. AI기술분류 코드 — 양식 붙임4가 OID 코드 체계로 되어 있어 분류표 부재. 관리기관에 확인
  4. 업로드 코드 3종 ↔ 데이터 유형(원시/가공/AI모델) 매핑 — 전달받은 설정 파일 3개가 모두 `jntp.conf` 로 동일 파일명이므로 원본 메일의 첨부 순서/폴더로 확인
  5. 데이터 공개 여부(전체/비공개), 라이선스, 이용정책 — 수요기업 생산정보 포함 여부에 따라 결정
  6. 수집 기간(장비 설치·광학 셋업 완료 시점), 일 검사 수량 — 3-1/5-1 의 예상 용량·건수 산정 근거
- 수량·용량은 **예상치(계획값)** 이며 실데이터 축적 후 개정한다(개정번호 관리, 붙임4 OID).
- 양식의 파란 글씨 예시(도로주행영상, 토양/기상 데이터 등)는 모두 AIVIS 내용으로 교체했다.

### 1-2. AI솔루션 모델 전체 개략도 및 과제 내용

**AI솔루션 모델(개략도)** — 절단 직후 검사 스테이션에서 제품 1개 단위로 길이·표면 부적합을 실시간 자동 판정하고, 결과를 DB·이미지 저장소에 적재해 MES 품질관리와 연계하는 7단계 파이프라인이다.

```
[제품 투입/정렬] → ① 이미지 취득(트리거·카메라·조명) → ② 영상 전처리(ROI·반사 보정·정규화)
   → ③ AI 분석 [길이 측정: 끝단 검출→px→mm 환산→공차 판정 | 표면 판정: 유분기/변색/스크래치 신뢰도]
   → ④ 종합 판정(OK/NG, 불량유형 코드 LEN/OIL/DIS/SCR/MULTI, 재확인 대상 분류)
   → ⑤ 데이터 저장(검사결과 DB + 원본/결과 이미지) → ⑥ MES 품질 DB 연계
   → ⑦ 사용자 서비스(작업자 HMI 실시간·NG 알람·재확인 입력 / 관리자 대시보드 이력·통계·KPI 리포트)
   → ⑧ 데이터 자산화: 원시·가공·AI분석 데이터셋을 전남 AX 오픈플랫폼 데이터포털에 정기 제출
```

| 단계 | 데이터셋 | 산출물 |
|---|---|---|
| ①~② 수집·전처리 | 원시 | 검사 원본 이미지, 촬영 메타 인덱스, 학습용 촬영본, 캘리브레이션 촬영 |
| 라벨링·재확인·기준정보 | 가공 | 결함 라벨(사이드카 JSON), 정답셋 매니페스트, 작업자 재확인(오검·미검) 라벨, 판정 기준정보 |
| ③~⑦ 분석·판정·서비스 | AI분석 | 제품별 판정 결과 레코드, 판정 오버레이 이미지, 월간 KPI, FAT/SAT/MSA 검증 리포트 |

**(데이터 수집)**

- 제품 도달 트리거(포토센서·디지털 IO, 시범 단계는 타이머) 발생 시 카메라가 제품 1개를 촬영하고, 원본 이미지(JPEG)와 촬영 메타(LOT·작업지시·품목·카메라 ID·촬영 시각·교대)를 검사결과 DB와 이미지 저장소에 저장한다. 한 프레임에 튜브 여러 개를 놓는 다중 튜브 모드에서는 프레임 1장이 튜브별 결과 N건과 연결된다.
- 촬영 조건을 고정한다: 수동 노출·게인·초점(자동노출/자동초점 금지), 확산광(유분기·변색)·저각도 사광(스크래치)·백라이트(길이 실루엣), 차광 후드·무광 배경판, 카메라 브래킷 고정. 품목별 촬영 레시피는 기준정보(`item_master.capture_recipe`)로 관리한다.
- 학습·검증용 촬영본은 별도 규격으로 수집한다: 클래스 폴더(OK/LEN/OIL/DIS/SCR/MULTI/BORDER) + 파일명 규칙 + 사이드카 라벨 JSON, 스케일 기준자(게이지)를 포함한 캘리브레이션 촬영, 세션별 조명·거리·치구 메타.

**(데이터 가공)**

- 전처리: 제품 영역 자동 분리(ROI), 길이 측정 영역과 표면 판정 영역 구분, 금속 반사 하이라이트 보정, 노이즈 제거·정규화. 원본은 수정하지 않고 파생 결과만 생성한다.
- 라벨링: 도입기업 품질담당(길이·정상)과 공급기업(유분기·변색·스크래치)이 공동 검수하여 이미지별 라벨 배열(복합불량은 2종 이상 기록)과 경계 샘플 여부를 사이드카 JSON 으로 기록하고, 정답셋 매니페스트(정확도·혼동행렬 산출용)를 구성한다.
- 운영 환류: 작업자가 HMI 에서 NG 재확인 결과를 입력하면 AI 판정과 사람 판정의 불일치(오검·미검)를 재확인 라벨로 축적하고, 품목별 임계값 보정 제안과 재학습 데이터셋 빌드에 사용한다. 판정 기준정보(기준 길이·공차·임계값·보정계수·촬영 레시피)는 버전 이력과 함께 스냅샷으로 남긴다.

**(데이터 분석)**

- 길이 측정: 고전 CV(적응형 이진화·Canny) 로 양 끝단 에지를 서브픽셀 정밀도로 검출하고 품목별 보정계수(px→mm)로 환산하여 기준 길이 대비 편차와 공차 OK/NG 를 판정한다.
- 표면 판정: 유분기(반사·얼룩 패턴 분류), 변색(LAB 색공간 이상영역), 스크래치(세그멘테이션·선형 흠집 검출)를 항목별 신뢰도 점수(0~1)로 산출한다. 초기 데이터 부족 구간은 고전 CV 폴백으로 동작하고, 데이터 축적 후 PyTorch 학습 → ONNX 배포 모델로 교체한다.
- 종합 판정: 길이+표면 통합 규칙으로 최종 OK/NG, 불량유형 코드(LEN/OIL/DIS/SCR/MULTI), 종합 신뢰도, 재확인 대상 여부, 처리시간(ms)을 결정적으로 산출한다. 결과는 DB·이미지 저장소·MES 에 적재되고 HMI/대시보드로 제공되며, 월간 KPI(공정불량률 ppm, 검사불량률, 자동검사율, 데이터 저장·MES 연계율, 평균 처리속도)와 FAT/SAT/MSA 검증 리포트를 산출한다.

| 활용분야 | 품질 추세·불량유형 통계 분석, 검사 모델 성능 모니터링·드리프트 감지, 공정 개선(절단·세척 조건 vs 불량률) 분석, 고객 대응 품질 이력 근거, 유사 금속 부품 검사 AI 벤치마크 |

## 붙임 A. 데이터셋 ↔ 포털 업로드 코드 대응 및 제출 방식 요약

| 데이터셋 | 포털 업로드 유형(설정 파일) | 데이터셋 루트 | 전송 주기 | 증분/스냅샷 |
|---|---|---|---|---|
| 원시 | 원시 데이터 (`jntp-raw.conf`) | `raw/` | 일 1회(02:17 KST) | `inspection/`·`index/` 증분(검사 시각 창), `capture/`·`calib/` 일괄 1회 |
| 가공 | 가공 데이터 (`jntp-processed.conf`) | `processed/` | 일 1회 | 전량 스냅샷(같은 경로 재전송 = 갱신) |
| AI분석 | AI 모델 (`jntp-ai-model.conf`) | `ai-analysis/` | 일 1회 | `inspections/`·`result/` 증분, `kpi/`·`reports/` 스냅샷 |

- 제출 파일은 `python -m portal.cli export|run`(`services/data-ops/portal`)이 위 명세 그대로 생성하며, A안(전남TP `upload.sh` + cron)과 B안(API 직접 호출) 중 현장 환경에 맞춰 선택한다. 두 방식은 같은 인터페이스(`POST /dataset-uploads`, `X-Dataset-Code`)를 쓰므로 데이터셋에 동일하게 누적된다.
- 개인정보 후보 필드(작업자·검수자·수정자)는 생성 단계에서 제외되며, 업로드 코드는 설정 파일(권한 600)로만 보관한다.
- 상세 절차·일정: [`JNTP_DATA_PORTAL.md`](./JNTP_DATA_PORTAL.md).
