## 1. 시스템 개요

### 1.1 배경

에이엠피는 차량·시스템 에어컨 열교환기용 Clad AL Header Pipe 를 생산한다. 길이 오차, 표면 유분기 잔존, 변색, 스크래치가 핵심 결함이며 현재는 **작업자 육안·수동 검사**에 의존한다. 금속 표면의 반사·곡면 특성과 작업자 숙련도·조명 환경에 따라 판정 편차가 발생하고, 검사 결과가 DB화되지 않아 불량 원인 추적·LOT 이력관리·품질 추세 분석·고객 대응자료 확보가 어렵다.

### 1.2 목적

절단 직후 구간에 AI 비전검사 스테이션을 두고 제품 1개 단위로 길이·표면 부적합을 **전수·실시간 자동 판정**하여 검사결과 DB에 적재하고 MES 품질관리와 연계한다.

1. 공정 내 불량 조기 차단
2. 출하 안정화
3. 전수선별 부담 제거
4. 품질 데이터 자산화

### 1.3 범위

**포함(SW 전부 + AI 추론 엔진)**: AI 추론 엔진, 검사 오케스트레이션, 백엔드 API·DB, 작업자 HMI, 관리자 대시보드, 기준정보 관리, 데이터·모델 운영 도구, 시뮬레이터·테스트 하니스.

**제외**: 카메라/렌즈/조명/트리거 센서/산업용 PC 등 **하드웨어 물리 구매·설치**(도입기업 자체 구축), 카메라 벤더 SDK 본체, MES 솔루션 본체, 경광등·부저 물리 결선. 단 각각에 대한 **연동 어댑터·연계 인터페이스·신호 발신 모듈**은 개발 범위에 포함한다.

### 1.4 운영 환경 (확정)

| 구분 | 사양 |
|---|---|
| 검사 장비 | Raspberry Pi 4 (4GB) + Camera Module 3 (IMX708) + 7" LCD |
| OS | Raspberry Pi OS (64-bit) |
| 실행 | systemd 단독 실행(`aivis-standalone.service`) — 부팅 시 자동 시작 |
| DB | SQLite(현장 단독) / PostgreSQL 16(다중 스테이션 확장 시) |
| 이미지 | 로컬 파일시스템 `/var/lib/aivis/images` (MinIO/S3 백엔드 선택 가능) |
| 네트워크 | 사내망. 인터넷 제한 환경 가정(오프라인 설치 지원) |

> 당초 계획의 산업용 PC + GigE 카메라 대신 **Pi 기반 엣지 구성**으로 확정되었다. 하드웨어 추상화 계층(HAL) 덕분에 상위 로직 변경 없이 카메라 어댑터만 교체하여 대응했다.

## 2. 인수 기준 (Acceptance Criteria)

### 2.1 AI 성능 목표 — FAT/SAT 합격 조건

| No | 성능항목 | 목표 | 측정 방법 | 현재 |
|---|---|---|---|---|
| P-1 | 자동검사율 | **100%** | AI 자동판정 완료수량 ÷ 총 검사대상수량 × 100 | 하니스 PASS(합성 데이터) |
| P-2 | 항목별 판정 정확도 | **95% 이상** | 정답셋 대비 길이/유분기/변색/스크래치 항목별 일치율 | **미측정 — 정답셋 확보 중** |
| P-3 | 검사 처리속도 | **300ms/ea 이하** | 이미지 취득~결과 저장 평균. p50/p95/p99 병기 | 하니스 PASS (p95 9~11ms) |
| P-4 | 데이터 저장 & MES 연계율 | **100%** | 정상 저장·연계 건수 ÷ 전체 검사 건수 × 100 | 하니스 PASS / **실 MES 미연계** |

**P-2 가 유일하게 미측정인 이유**: 정확도는 정답셋 없이 잴 수 없다. 검사 이미지는 충분히 쌓였으나 "이 사진이 유분기인지 변색인지"를 사람이 판정한 기록이 없었다. 이를 위해 라벨링 화면(§3 M16)을 구축했고, 검수가 진행되는 만큼 측정이 가능해진다.

### 2.2 사업 KPI

| 분야 | KPI | 단위 | 구축 전 | 목표 | 산출 |
|---|---|---|---|---|---|
| 품질 | 공정불량률 | ppm | 2,000 | 600 이하 | 자동 (공정 중 불량 ÷ 총 검사) |
| 품질 | 출하유출불량률 | ppm | — | 1,000 이하 | 반자동 (출하수량·유출 부적합 수기 입력 필요) |
| 품질 | 검사불량률(오검+미검) | % | 수동의존 | 30 이하 | 자동 |
| 품질 | Claim 건수 | 건/년 | 5 | 2 이하 | 수기 입력 |
| 원가 | 작업공수 절감률 | % | 100 | 50 이하 | 수기 입력 |
| 납기 | 수주출하 리드타임 | 일 | 7 | 5 이하 | 수기 입력 |

> ⚠️ **확인 필요 사항**: 개발지침(CLAUDE.md §1.1)은 **공정불량률 600ppm / 검사불량률 30%** 를, 계약 성과지표는 **출하유출불량률 1,000ppm / 검사불량률 40%** 를 인수 기준으로 삼는다. 두 불량률은 이름만 다른 것이 아니라 분자·분모가 모두 달라 서로 환산할 수 없다(걸러낸 불량 ÷ 검사수량 vs 유출된 부적합 ÷ 출하수량). 시스템은 **두 지표를 모두 산출**하고 리포트에 나란히 싣는다. 어느 쪽을 합격 판정 기준으로 삼을지는 계약 확인 후 환경변수(`AIVIS_KPI_TARGET_*`)로 고정한다.

**완료기준**: 항목별 판정 정확도 ≥ 95%(정답셋 기준) — 정답셋 확보 후 측정.

## 5. 검증 방법

### 5.1 자동 검증 현황

| 영역 | 테스트 수 | 도구 |
|---|---|---|
| 비전 파이프라인 | 280 | pytest |
| 백엔드 API | 166 | pytest |
| 관리자 대시보드 | 118 | Vitest + Testing Library |
| 작업자 HMI | 64 | Vitest + Testing Library |
| 데이터 운영(라벨링·재학습) | 22 | pytest |
| FAT/SAT/E2E 하니스 | 15 | pytest |
| **합계** | **665** | |

전 테스트는 **실물 카메라 없이**(`AIVIS_CAMERA=sim`) 통과한다.

### 5.2 인수 시험 계획

| 단계 | 내용 | 상태 |
|---|---|---|
| FAT | 샘플 기반 기능·성능 시험(이미지취득/판정/DB저장/UI/MES) | **하니스 완료, 합성 데이터로만 실행** |
| SAT | 실생산품 기준 자동검사율·정확도·처리속도·저장률·연계율·사용성 | **미실시** |
| MSA | 동일 샘플 30회 반복 → 반복성·재현성(GR&R) | **하니스 완료, 실물 미실시** |
| 시범운영 | LOT별 이력·불량유형 통계·월간 KPI | 미실시 |
| 교육 | 작업자·관리자 교육 | 미실시 (운영 매뉴얼은 작성 완료) |

**FAT/SAT/MSA 는 도구가 아니라 실물 시료와 일정의 문제다.** 자동 검증 하니스는 완성되어 있어, 실생산품과 정답 판정만 주어지면 즉시 실행하고 결과서를 산출한다.

## 6. 제약 조건 및 가정

| 구분 | 내용 |
|---|---|
| C-1 | 카메라·조명·치구·트리거 센서는 도입기업이 설치한다. 광학 셋업이 고정되기 전 촬영분은 학습·검증에 쓸 수 없다(조명·각도·스케일 비표준). |
| C-2 | 길이 측정에는 **스케일 기준자**가 같은 평면에 함께 촬영되어야 한다(px-mm 환산). |
| C-3 | 라벨(정답) 검수 주체는 도입기업 품질담당이다(유분기·변색·스크래치는 도입+공급 공동 검수). |
| C-4 | 연계 대상 MES 가 확정되어야 실연계 시험이 가능하다. |
| C-5 | 현장 파이는 인터넷이 제한될 수 있어 오프라인 설치를 전제한다. |
| C-6 | SD카드 용량이 유한하므로 이미지 보관기간에 상한이 있다. 장기 보관이 필요하면 외장 저장장치를 마운트한다. |

## 7. 현재 남은 작업

| # | 항목 | 막고 있는 것 | 해소 방법 |
|---|---|---|---|
| 1 | 표면 모델 실데이터 학습(M4) | 라벨링된 정답셋 | 라벨링 화면 가동 → 클래스별 최소 수량 확보 → 학습·임계 교정 |
| 2 | MES 실연계(M9) | 연계 상대 미확정 | 규격서 전달 → 방식·접속정보 확정 → 8단계 시험 |
| 3 | 실물 FAT/SAT/MSA | 실생산품 시료·일정 | 하니스는 준비 완료. 시료 확보 후 실행 |
| 4 | 교육·인수검수 | 위 1~3 완료 | 운영 매뉴얼 기반 교육 실시 |

**1~4 는 순서가 있다.** 정답셋 없이는 정확도를 잴 수 없고, 정확도 없이는 SAT 를 통과할 수 없다. 따라서 **정답 라벨링이 가장 앞선 실행 항목**이다.
